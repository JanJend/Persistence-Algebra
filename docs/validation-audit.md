Scope: the headers directly in `include/grlina`. IDs correspond to the inventory
provided in the conversation. The working tree already contained matrix and solver changes when
this audit began; use the ID and operation name rather than old line numbers.

## Reachability and policy

Most matrix storage, dimensions and degree vectors are public. Invalid data is
therefore not globally excluded by the type system: callers can supply arbitrary
vectors or edit them directly. These are caller contracts, rather than a reason
to revalidate every operation.

Conditions excluded by valid algorithm construction are internal diagnostics.
Tautological checks and redundant whole-data scans are removed where they add
no useful diagnostic. Mathematical tests that compute the answer, unsupported
operations, representability limits, file parsing, and actual resource/I/O
failures remain meaningful in optimized builds.

`GRLINA_ENABLE_CHECKS` retains its existing policy:
- Default checks on for an unoptimized build without `NDEBUG`.
- Default checks off under `__OPTIMIZE__` or `NDEBUG`.
- Explicit `GRLINA_ENABLE_CHECKS=0` or `=1` overrides the default.
- Define the override consistently across translation units.
- Disabled diagnostic blocks and assertions do not evaluate their expressions.

Following the October 11 selection, matrix, chain-complex, Homomorphism,
Submodule, epsilon and grid validators have been removed, including their
callers in diagnostic builds and the full post-load structural scan.
`is_chain_complex()` directly multiplies adjacent differentials and tests zero;
`squares_to_zero()` has been removed. `check_lifts()` remains explicit and is
not used by library operations. The IS2 block-size overflow guard is removed.

Sorting metadata is a plain boolean. No degree-order scans or comparator
validation remain. Constructors/readers leave unknown order false; sorting
both axes sets it true. Partial sorts leave it false unless the untouched axis
has at most one degree. Sorted-input preconditions inspect only the flag.
Direct degree edits require the caller to maintain that flag.

The later CC13 selection removes `poset_identifier()`,
`runtime_poset_identifier()` and the runtime-poset context helpers and state.
SCC I/O obtains the identifier directly from the serialized degree's traits.
`is_sorted_sparse()` remains an explicit query, delegating each column to the
strict-order helper through the storage accessor; it adds no automatic scan.

## Missing-include repair

The removed `runtime_matrices` directory left active root headers and build
rules pointing at nonexistent files. The repair reuses the committed generic
storage, SCC metadata, geometry, chain-basis, Hom-space and module-transformation
helpers at root-level include paths. CSC storage, column views and storage traits
live in `include/grlina/storage/csc.hpp`; the matrix alias lives alongside
`SparseMatrix` in `include/grlina/matrices/sparse.hpp`. Raw offset validation is
debug-only, including its ordering scan. Current coordinate/grid tests use `mat_coord.hpp` and
`mat_grid.hpp` with compile-time dimensions; Gaussian tests retain the sparse
and dense backends.
Grid submodule shifts and epsilon diagonals use physical coordinates instead of
the removed runtime-dimension dispatch, and the R2 grid dimension is checked at
compile time.
The baseline-comparison benchmark uses the current fixed two-dimensional grid
matrix and its graded kernel for the reference computation.

The CSC matrix, graded/module and warning suites are registered again. Four
suites still depend entirely on removed runtime-dimensional types and remain
unregistered: `dynamic_coordinate_matrix_test`, `dynamic_grid_matrix_test`,
`general_coordinate_kernel_test`, and `library_interop_test`. Their source files
are preserved. Validation scans inside subdirectory matrix implementations are
outside the original root-header scope.

## Verification

The validation-policy test exercises default debug, default optimized, forced-on
and forced-off modes. It checks that constructors trust data, sorting flags do
not trigger scans, explicit chain-equation queries return the mathematical
result, and algebra/serialization agree in all four modes. The algebra suites
retain equation, coefficient and degree comparisons after validator removal.

After the October 11 removals, CC13 cleanup and CSC restoration, all 27
registered tests passed, including the four check-policy modes and the restored
CSC suites. Existing GRLINA_ASSERT conditions are unchanged by these removals.
The sparse and CSC column tests cover empty, singleton, ascending, descending
and duplicate entries, including borrowed CSC views and column boundaries.
The CSC matrix suite also passes in an optimized build with checks disabled by
default, verifying that raw offset validation follows the selected policy.

A subsequent concurrent header rename interrupted the full rebuild with
temporarily missing includes. The CSC matrix and graded/module targets were
rebuilt successfully against the current `mat_*`/`hom_*` header names.
All three CSC suites passed again, including the C++17/C++20 warning checks.
